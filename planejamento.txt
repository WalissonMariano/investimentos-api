A ideia do endpoint está boa. O ponto central é separar **três perguntas diferentes** e responder todas com o mesmo capital e o mesmo período.

## O que o termômetro responde

Não é “dólar vs CDI vs IPCA” como se fossem a mesma coisa. São **benchmarks com papéis diferentes**:

| Indicador | Pergunta |
|-----------|----------|
| **IPCA** | Meu dinheiro **manteve poder de compra**? |
| **CDI** (preferível à Selic meta) | Quanto eu teria se tivesse rendido **juros de mercado**? |
| **Dólar** | Quanto eu teria se tivesse ficado **em USD**? |

A pergunta do seu `planejamento.txt` (“CDI 10%, dólar +12%, IPCA 5% — ganhei de verdade?”) se resolve assim:

- **Ganho nominal** = variação do ativo/estratégia  
- **Ganho real** = ganho nominal **descontado o IPCA**  
- **Perdeu poder de compra** = se o retorno ficou **abaixo do IPCA**

## Lógica do endpoint

**Entrada sugerida**

```http
GET /api/termometro?valor=10000&moeda=BRL&data_inicio=2024-01-01&data_fim=2024-12-31
```

- `valor` + `moeda` (`BRL` | `USD`)
- `data_inicio`, `data_fim`
- opcional: `benchmark_juros=CDI` (padrão) — Selic over só se quiser comparar a taxa do BC, não o rendimento típico de investimento

**Passos internos**

1. **Normalizar o capital na data início**  
   - Se `moeda=BRL` → capital base = `valor`  
   - Se `moeda=USD` → `capital_brl = valor * usd(data_inicio)`

2. **Buscar séries no período**  
   - USD/BRL: cotação início e fim (dia útil mais próximo) — AwesomeAPI  
   - IPCA: meses cobertos — BCB SGS (ex.: série **433**)  
   - CDI: fator acumulado no período — BCB SGS (série **12**)  
   - Evite Selic meta (série 432) para “quanto eu teria rendido”; use **CDI** ou Selic over (série **11**)

3. **Calcular fatores acumulados**

```text
fator_ipca  = Π (1 + ipca_mês/100)          // meses do intervalo
fator_cdi   = Π (1 + cdi_dia/100)           // dias úteis (ou fator do BCB)
fator_usd   = usd_fim / usd_inicio
```

4. **Simular o capital em cada cenário**

```text
// dinheiro parado em R$ (colchão)
final_caixa   = capital_brl                         // nominal igual
real_caixa    = capital_brl / fator_ipca            // poder de compra

// 100% CDI
final_cdi     = capital_brl * fator_cdi
real_cdi      = final_cdi / fator_ipca

// parado em dólar (marcado em R$)
final_usd     = capital_brl * fator_usd
real_usd      = final_usd / fator_ipca
```

5. **Ganho/perda**

```text
ganho_nominal = final - capital_brl
ganho_real    = real  - capital_brl   // ou: final/fator_ipca - capital_brl
```

O número mais honesto para “perdi ou ganhei dinheiro” é o **ganho real** (vs IPCA). O nominal sozinho engana.

## Exemplo numérico

Capital: **R$ 10.000** | CDI **+10%** | Dólar **+12%** | IPCA **+5%**

| Cenário | Final nominal | Poder de compra | Ganho real |
|---------|---------------|-----------------|------------|
| Caixa (R$) | 10.000 | 9.524 | **-476** |
| CDI | 11.000 | 10.476 | **+476** |
| Dólar | 11.200 | 10.667 | **+667** |

Conclusão: CDI e dólar **ganharam** em termos reais; caixa **perdeu** poder de compra. Dólar ganhou **mais** que o CDI nesse período (não significa que sempre ganha).

## Formato de resposta sugerido

```json
{
  "periodo": { "inicio": "2024-01-01", "fim": "2024-12-31" },
  "capital_inicial_brl": 10000,
  "fatores": {
    "ipca": 1.05,
    "cdi": 1.10,
    "usd": 1.12
  },
  "cenarios": {
    "caixa":  { "final_nominal": 10000, "poder_compra": 9523.81, "ganho_real": -476.19 },
    "cdi":    { "final_nominal": 11000, "poder_compra": 10476.19, "ganho_real": 476.19 },
    "dolar":  { "final_nominal": 11200, "poder_compra": 10666.67, "ganho_real": 666.67 }
  },
  "veredito": {
    "melhor_cenario": "dolar",
    "cdi_bateu_ipca": true,
    "dolar_bateu_ipca": true,
    "dolar_bateu_cdi": true
  }
}
```

Para o gráfico (Recharts), o endpoint pode ainda devolver **séries mensais** (`capital × fator acumulado até aquele mês`) em vez de só o ponto final.

## Cuidados importantes

1. **IPCA é mensal** — período parcial (ex.: 15/jan → 10/mar) precisa de regra clara: só meses fechados, ou IPCA proporcional. Documente isso na API.  
2. **Dólar e CDI são diários** — use dias úteis; se não houver cotação na data, pegue o dia anterior.  
3. **CDI ≠ Selic meta** — para “investi no CDI”, use série CDI.  
4. **Não misture “perdi” sem contexto** — diga sempre: perdeu vs IPCA, vs CDI ou vs dólar.  
5. **Cache local** — grave as séries no Postgres; não chame BCB/AwesomeAPI a cada request.  
6. **Moeda USD na entrada** — converta no início; o termômetro compara em **BRL + poder de compra (IPCA Brasil)**. IPCA não mede inflação dos EUA.

## Fluxo resumido

```text
request → normaliza capital em BRL na data início
       → busca/acumula IPCA, CDI, USD no intervalo
       → projeta 3 cenários (caixa, CDI, dólar)
       → desconta IPCA para ganho real
       → retorna valores + veredito (+ série para gráfico)
```
